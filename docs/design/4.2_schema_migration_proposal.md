# 4.2 — ex-VAT capture: schema & migration proposal

*The "how" for the model in `billing_rounding_and_exvat_design.md` (the "why"). Goal: capture
the purest inputs at import so the inc-VAT bill can later become a derived, banker's-rounded
view — with **no re-import**, and with less drift **even for offline users**. Everything here is
**additive and default-off**: inc-VAT `imp_rate`/`imp_cost`, the Total Bill, and all current
charts/stats stay **byte-identical** (same guarantee proven for the 4.1.3 `imp_cost_exc` column).*

---

## 1. New `blocks` columns (all nullable REAL/TEXT, additive)

| column | type | meaning |
|---|---|---|
| `imp_cost_exc` | REAL | ex-VAT import cost. **Already added in 4.1.3.** |
| `imp_rate_exc` | REAL | ex-VAT import unit rate, **full precision, unrounded**. Stored explicitly (not derived from `cost÷kWh`) so a zero-cost/zero-kWh slot still carries the published rate. |
| `standing_charge_exc` | REAL | ex-VAT daily standing charge (mirrors `standing_charge`, which is inc-VAT, on the main import row). |
| `exc_source` | TEXT | provenance of the exc figures for this block: `measurement` \| `tariff` \| `bill` \| `csv` \| `approx` \| NULL (no exc). Tells a future derived-view what is exact vs recomputed. |
| `exp_cost_exc` | REAL | *(optional, phase D+)* ex-VAT export credit. Domestic export is usually 0-rated (exc == inc), so low priority; include for symmetry / non-domestic. |
| `exp_rate_exc` | REAL | *(optional, phase D+)* ex-VAT export rate. |

**VAT is NOT a column** — it's derived on read as `imp_cost ÷ imp_cost_exc − 1` (or `imp_rate ÷ imp_rate_exc − 1`) wherever both sides exist. Future-proof: when VAT is removed, `inc == exc` → 0%.

### Migration
Add each to the idempotent ADD-COLUMN list in `block_store.py` (alongside the 4.1.3 `imp_cost_exc` entry) **and** to the `CREATE TABLE blocks` body:
```
("imp_rate_exc",        "blocks", "REAL", _b_cols),
("standing_charge_exc", "blocks", "REAL", _b_cols),
("exc_source",          "blocks", "TEXT", _b_cols),
# ("exp_cost_exc", …), ("exp_rate_exc", …)  # phase D+
```
Existing rows → NULL. No backfill in the migration itself.

## 2. Store round-trip (mirror the 4.1.3 `imp_cost_exc` work)

- **`_block_rows`** (write): emit `imp_rate_exc`, `standing_charge_exc`, `exc_source` (and export exc if in scope) from the channel/meter dict — `imp.get("rate_exc")`, `meter_block.get("standing_charge_exc")`, `meter_block.get("exc_source")`.
- **`_insert_block_rows` + `_insert_block_rows_replace`**: add the new columns + `:named` params (both statements).
- **`_row_to_block`** (read): surface them back onto the channel/meter dict, guarded for older DBs (as `imp_cost_exc` already is), so any read→modify→rewrite round-trip preserves them.

*This slice alone (schema + round-trip) is the low-risk foundation, exactly like 4.1.3.*

## 3. Capture points (where each figure is set)

| source | path | cost_exc | rate_exc | exc_source |
|---|---|---|---|---|
| API measurement | `engine.py` main import loop (~6298) + recovery (~6351) → `upsert_imported_blocks` | `r.get("cost_excl")` | from tariff exc-rate (§4) or `cost_excl÷kWh` | `measurement` |
| API tariff-priced (no meas cost) | same loop, `else` branch | `kWh × exc_rate` | tariff exc-rate (§4) | `tariff` |
| live / settlement | `engine.py` ~6635/6670/6706 → block-dict → `append_block_replace` | from node `cost_excl` / tariff | tariff exc-rate | `measurement`/`tariff` |
| PDF bill | `bill_parser` → CSV v2 → importer | `cost_pre` | `rate_pre` | `bill` |
| hand CSV (v2 cols populated) | CSV importer | exc cost col | exc rate col | `csv` |
| fallback (no exc) | — | NULL | NULL | NULL → block stays **inc-only** (no ex features; no synthesis) |

`upsert_imported_blocks` gains the exc columns; `rows_to_write` dicts gain `cost_exc` / `rate_exc` / `standing_exc` / `exc_source`.

## 4. `RateSchedule` — carry the exc rate

`from_api_records` currently keeps only `value_inc_vat` (kraken_rates.py:168). Change the period
tuples to carry **both** (`vfrom, vto, inc, exc`) and add `exc_rate_at(ts)` (or have the
existing resolver return `(inc, exc)`). This unlocks the API tariff-priced path **and** the CSV
`inc÷1.05`-avoidance where an account is connected. No behaviour change to the inc path.

---

## 5. No VAT default — inc-only blocks accept the limitation

There is deliberately **no configured VAT default**. A block with no exc figure and no API/bill
has no ex-VAT ground truth; synthesising one via `inc ÷ (1+VAT)` is fabricated precision (inc is
a rounded gross-up of ex) and bill-method rounding on it is a double approximation that still
won't match the bill. It isn't needed for the derived-view model either — for an inc-only block
the "derived bill view" is simply the stored inc. So such blocks stay **inc-VAT only**, and
ex-VAT display / bill-method rounding are **unavailable and clearly labelled** for them. VAT is
only ever derived from a real `inc/exc` pair; the 2026 removal and future changes need no default
(pair → `inc == exc` → 0%).

## 6. Read-side helpers (for BL-24 later; not wired now)

- `vat_rate_for(block)` → `imp_cost ÷ imp_cost_exc − 1` when both present, snapped to the nearest
  legislated band (0/5/20%); else **None** (block is inc-only — no ex/VAT, no synthesis). Small
  rounding noise is expected — use for *identifying* the band, prefer showing stored inc/exc directly.
- Upgrade `bill_slots_from_blocks` to prefer stored `imp_rate_exc` / `imp_cost_exc`, then tariff
  exc, then `inc÷1.05`.

## 8. Buildable slices (each independently shippable + validated)

- **A — schema + round-trip.** Columns, migration, `_block_rows`/`_row_to_block`, tests. Validate: existing DB migrates, new cols NULL, `SUM(imp_cost)` and all inc figures **byte-identical** (repeat the 4.1.3 dev-DB check). *Lowest risk; land first.*
- **B — `RateSchedule` exc.** Carry exc series + `exc_rate_at` + unit tests. No inc change.
- **C — capture (API + live).** Wire cost_exc/rate_exc/standing_exc/exc_source into the measurement, tariff, and live/settlement paths; extend `upsert_imported_blocks`. **Golden-baseline check**: billing summary + blocks-summary JSON byte-identical to pre-change (inc unaffected); spot-check `exc_source` distribution + `inc/exc` VAT ≈ 5% on the dev DB.
- **D — CSV/bill v2.** `bill_parser` emits exc columns; importer prefers-when-populated; blank template + docs. Back-compat test: an inc-only CSV imports unchanged.
- **(BL-24, separate gate)** — opt-in `bill_rounding` totals mode + inc/exc display toggle, once C/D have real exc in the field. Gate ex-VAT display / rounding on ex being present; inc-only blocks show inc as today, clearly labelled.

*(There is no VAT-default slice — see §5.)*

---

## 9. Invariants / risk

Every inc-VAT figure and the Total Bill stay byte-identical through slices A–E (nothing reads the
exc columns until BL-24 opts in). All new columns nullable; guarded reads for old DBs. Each slice
carries its own golden/byte-identical check; ship a slice only if the inc diff is empty.
