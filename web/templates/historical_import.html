Import half-hourly history from your supplier. This is a best-endeavours reconstruction: imported blocks are flagged and can be removed at any time (Delete Blocks → reconstructed history). Two routes: the API (Octopus) fetches each half-hour's kWh together with Octopus's own billed cost and off-peak/peak label — so it's exact and dispatch-aware, including IOG, and reaches your full history. The CSV route is for non-Octopus suppliers or an offline website export.
API import — Octopus, full history
Each half-hour comes with Octopus's billed cost + OFF_PEAK/STANDARD_RATE label, so the rate and off/peak split are exact — a smart-charged evening slot is correctly priced off-peak (no tariff lookup, IOG included). If a slot comes back without its cost (Octopus can drop it when the connection is busy), the import quietly re-fetches that slot on its own and prices it from the real figure. Reversible via Delete Blocks → reconstructed history.
This can take a while. Octopus rate-limits the API and gets progressively stricter the harder it's pushed, so the import runs in paced, resumable steps and eases off automatically when the hourly allowance runs low (it pauses and resumes on its own — leaving budget for your live readings). Other apps on the same Octopus account share that allowance — the Octopus app, the Home Assistant Octopus (BottlecapDave) integration, or any other API tool — so if one of those is busy at the same time, the import will slow down or pause until the budget recovers. That's expected; just leave it running.
After the import, a background pricing check runs to give the smart-charge (IOG) half-hours their exact off-peak price. It's rate-limited the same way, so on a large multi-year history — or while other apps are using the account — it can take a good while and will pause and resume on its own. You don't need to wait or do anything; the pricing-health panel below shows its progress and updates when it's done.
Confirm your sites
Your Octopus account shows more than one address across this history. Name each past address so its data is filed under the right site and DNO region before the import runs. Your current site keeps its name (it's this instance's identity).
Repair tools — only if a rate still looks wrong
A healthy import needs none of these — the pricing health panel above shows if anything's outstanding, and offers a one-click retry for any flagged slots. This re-fetches half-hours with a calm query and re-prices them from Octopus's real billed figures.
Re-checks every imported half-hour in the range — flagged or not — and re-prices each. Use when a rate looks wrong on a slot that already has a cost (e.g. after a tariff or price-cap change, where the rate no longer matches the cost). Flagged-slot mode can't reach these — they were never flagged. By default it fixes import only; tick also fix export to collapse a fragmented flat/Agile export rate back to its clean scheduled value. It tells you how many blocks it will touch and asks you to confirm first. Start with a narrow range (a week), then widen.
In the results: re-priced = slots corrected · not recovered = Octopus didn't return a cost this pass (usually a busy connection — re-run to retry).
Match the bill exactly (from CSV) — last resort. Almost every slot can be fixed by the automatic verify pass, the health-panel retry, or the date-range tool above. Only if a handful still won't price after repeated repair, download the Octopus consumption CSV for the affected period and upload it here to set each half-hour's cost straight from your bill.
